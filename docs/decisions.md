# Foundation decisions

2026-10-23. These implement the current Milestone 1 brief, which supersedes earlier product assumptions. The earlier media experiments in the previous workspace are not part of this monorepo.

- **Scope:** one platform; registration is eventually open, application access requires approval. Approval and channel management will be available to all approved users; owner-only removal/security changes remain future authorization work. No implementation of these roles is implied by the shell.
- **Stack:** TypeScript 6, React 19, Vite 8, Electron 45, Fastify 5, Socket.IO 4, Drizzle, PostgreSQL 17, pnpm workspaces, ESLint, Prettier, and Vitest. Registry version discovery and actual peer/build checks were used. TypeScript 7 was rejected by typescript-eslint, so the compatible 6.0 line is pinned. The lockfile is authoritative.
- **Shared frontend:** Electron loads Vite in development and the same built web assets otherwise. Reusable UI primitives and event types are separate workspace packages. The renderer has no Node.js access.
- **Electron:** context isolation, sandbox, and web security stay enabled. Permission requests, external windows, navigation, and webviews are denied. The frozen preload surface only reveals platform/version; no filesystem, arbitrary IPC, credentials, or shell execution are exposed. No capture or microphone permission exists.
- **Local connection boundary:** API binds to 127.0.0.1 by default. Browser origins are allowlisted, plus opaque/file origins for built Electron. Socket.IO is intentionally unauthenticated and only exposes welcome/ping events. Origin checks are not authentication. Before introducing protected resources or hosting, replace this development boundary with authenticated sessions and a deliberate desktop origin/session design. Keep this milestone local.
- **CSP:** production permits only local scripts; Vite's inline development preamble is allowed only during development. Network access is limited to the local API and Vite socket. Changing the API host also requires deliberately updating CSP and allowed origins.
- **Database:** one minimal user table with pending approval by default, no passwords or account behavior. SQL migrations are generated and checked in. Application startup does not require PostgreSQL until data-backed features are introduced. Migration failure closes the pool and exits with an error.
- **UI honesty:** messages, member profiles, voice controls, settings and account identity are visibly placeholders. Only channel selection, notices, navigation and connection health are functional. No mock messages are sent or saved.
- **Future privacy:** administrators do not gain private conversation access. Group invitations require acceptance; history access must use membership intervals, including prior authorized periods but excluding absences. Message deletion belongs to authors. These remain requirements for later milestones, not features implemented here.
- **Deployment:** no cloud resources, native media integrations, installer, auto-update, or public repository were created. Mobile browsers and multiple desktop platforms need later compatibility testing; this milestone was exercised on Windows 11.

- **Database verification (2026-10-23):** PostgreSQL 17.11 is healthy on 127.0.0.1 only. Migrations, real database tests, Fastify readiness over HTTP, and restart persistence passed. Credentials remain ignored. Historical experiments are preserved locally and excluded from the verified foundation commit.
