# Rajcord Windows OBS sender

`obs/source-build.json` records the OBS revision, verified dependency archives and native transport for this bundle. `versions.txt` records the libdatachannel revision and the transport dependency build inputs.

Screen shares that include audio require Windows Audio. The helper checks the service's status and reports an affected share failure when Windows stops supplying audio. Its service access is read-only.

The private Windows x64 bundle uses source-built OBS for capture, Direct3D11 and encoding. It stages libobs, WinRT, Game Capture, OBS NVENC, the OBS FFmpeg module containing AMD AMF, and OBS x264. The AMD and NVIDIA runtimes come from the installed display driver. Windows process-loopback WASAPI supplies timestamped 48 kHz stereo PCM. libopus encodes at the capture rate. libdatachannel provides encrypted WebRTC media, libnice provides ICE and TURN, and OpenSSL supplies TLS and cryptography.

The helper links to GPL-licensed libobs and can load GPL-licensed encoder modules. The OBS package is for local verification while redistribution is blocked. Applicable corresponding-source inputs include the combined helper, OBS, x264, FFmpeg, the native transport dependencies and their build scripts and notices. Review the NVIDIA and AMD SDK and driver terms, the exact FFmpeg build, the transport notices and the applicable codec rights before distribution. [OBS license](https://github.com/obsproject/obs-studio/blob/33.0.1/COPYING) · [FFmpeg legal](https://ffmpeg.org/legal.html) · [AMD AMF](https://github.com/GPUOpen-LibrariesAndSDKs/AMF) · [NVIDIA Video Codec SDK](https://developer.nvidia.com/video-codec-sdk)

The pinned OBS runtime uses FFmpeg n8.1.2 with `--enable-gpl --enable-version3 --enable-libx264`. Its OBS x264 DLL reports 0.164.3106 eaa68fa. The package audit checks for accidental QSV and oneVPL files. See [the source manifest](corresponding-source.md) for the binary-to-source mapping and source-package gaps.

The OBS AMF texture encoder uses the AMD SDK inside `obs-ffmpeg.dll`. The module also links FFmpeg for other OBS features, so disabling the FFmpeg external x264 wrapper is a separate decision from keeping Rajcord's OBS x264 fallback. The audit candidate uses `--disable-gpl --disable-version3 --disable-nonfree --disable-libx264` and retains the FFmpeg shared libraries. It satisfies all FFmpeg imports recorded from the staged OBS binaries, and both audio scopes passed repeated local playback with it. Its build script is [build-ffmpeg-candidate.sh](build-ffmpeg-candidate.sh). Replacing the installer libraries still requires physical Radeon acceptance and corresponding-source review. The installer uses the pinned OBS FFmpeg build while that work is open. Libobs and the standalone OBS x264 fallback each retain their GPL terms. [OBS module build](https://github.com/obsproject/obs-studio/blob/33.0.1/plugins/obs-ffmpeg/CMakeLists.txt) · [FFmpeg licensing](https://ffmpeg.org/legal.html)

The `inventory.json` file identifies the exact DLLs and data staged in the installer. `licenses/` includes libdatachannel, libSRTP, usrsctp and the vcpkg dependency notices, including libnice, OpenSSL and Opus. The bundle carries the x64 Visual C++ redistributable DLLs identified by the native binaries' import tables. [Microsoft Visual C++ redistribution](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files)

Rajcord rebuilds `libobs-winrt.dll` and `obs-nvenc.dll` from pinned sources with the capture-interval, diagnostic and H.264 low-latency patches. The NVENC plugin uses nv-codec-headers 13.0.19.0 and ships their notices under `obs/nv-codec-headers-license.txt`. The desktop app launches the helper over inherited pipes and exchanges signaling, authorization deadlines and capture controls. The distribution review covers those links together with the exact upstream, generated and patched sources and build recipes.
